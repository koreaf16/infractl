# 설정 구성

## 개요

Claude Code의 설정은 여러 소스에서 병합되며, 우선순위가 높은 설정이 낮은 설정을 덮어쓴다.

---

## 설정 소스 우선순위

```
낮은 우선순위
    1. managed       — 기업 관리자 정책 (/etc/claude-code/managed-settings.json)
    2. user          — 전역 사용자 설정 (~/.claude/settings.json)
    3. project       — 프로젝트 설정 (.claude/settings.json, CLAUDE.md 동위)
    4. local         — 프로젝트 개인 설정 (.claude/settings.local.json)
    5. flag          — CLI 플래그 오버라이드 (--model 등)
    6. session       — 세션 중 /config 변경 (런타임, 휘발성)
높은 우선순위
```

---

## 설정 파일 경로

| 소스 | 경로 |
|------|------|
| managed | `/etc/claude-code/managed-settings.json` (Linux/macOS) |
| user | `~/.claude/settings.json` |
| project | `.claude/settings.json` |
| local | `.claude/settings.local.json` |

**Windows MDM:** `HKCU\Software\Anthropic\Claude Code` 레지스트리 키

## SettingsJson 주요 구조

`utils/settings/types.ts`에 Zod로 정의된 전체 설정 스키마:

```typescript
type SettingsJson = {
  // 모델
  model?: string                    // 기본 모델
  smallFastModel?: string           // 빠른 작업용 모델

  // 권한
  permissions?: {
    allow?: string[]                // alwaysAllow 규칙 목록
    deny?: string[]                 // alwaysDeny 규칙 목록
    additionalDirectories?: string[] // 추가 작업 디렉토리
  }

  // MCP 서버
  mcpServers?: Record<string, McpServerConfig>

  // 훅
  hooks?: {
    [event: HookEvent]: HookMatcher[]
  }

  // 동작 설정
  autoUpdaterStatus?: 'enabled' | 'disabled'
  verbose?: boolean
  theme?: ThemeName
  preferredNotifChannel?: 'terminal_bell' | 'iterm2' | 'system'

  // 기업/관리
  disableNonEssentialTraffic?: boolean
  policyLimits?: PolicyLimits
}
```

## 설정 로딩 (settings.ts)

```typescript
// utils/settings/settings.ts
getInitialSettings()        // 모든 소스 병합 (lodash mergeWith)
getSettingsForSource(src)   // 특정 소스만 읽기
```

### 병합 전략

```typescript
// lodash mergeWith로 deep merge
// 배열 필드(permissions.allow 등)는 concat 병합
// 스칼라 필드는 높은 우선순위가 덮어씀
```

### 캐싱

`utils/settings/settingsCache.ts`가 파일 읽기 결과를 캐싱한다.

```typescript
getCachedSettingsForSource(source)
setCachedSettingsForSource(source, settings)
resetSettingsCache()   // 설정 변경 시 캐시 무효화
```

## MDM (Mobile Device Management)

`utils/settings/mdm/`가 기업 정책을 관리한다.

```typescript
// 플랫폼별 정책 읽기
getMdmSettings()        // macOS: plist / Linux: /etc/
getHkcuSettings()       // Windows: 레지스트리 HKCU
```

**병렬 읽기:** `startMdmRawRead()` (main.tsx 최상단)에서 서브프로세스를 미리 실행해,  
실제 필요 시점에 결과를 기다린다.

## 환경변수

`utils/env.ts`와 `utils/envDynamic.ts`가 환경변수를 관리한다.

### 주요 환경변수

| 변수 | 역할 |
|------|------|
| `ANTHROPIC_API_KEY` | API 키 |
| `CLAUDE_CODE_USE_BEDROCK` | AWS Bedrock 사용 |
| `CLAUDE_CODE_USE_VERTEX` | GCP Vertex AI 사용 |
| `CLAUDE_CODE_REMOTE` | 원격 환경 플래그 |
| `CLAUDE_CODE_DISABLE_AUTO_MEMORY` | 자동 메모리 비활성화 |
| `CLAUDE_CODE_MAX_TOOL_USE_CONCURRENCY` | 동시 도구 실행 수 |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW` | 자동 컴팩트 윈도우 크기 |
| `DISABLE_BACKGROUND_TASKS` | 백그라운드 태스크 비활성화 |
| `ANTHROPIC_BASE_URL` | API 엔드포인트 오버라이드 |

### applyConfigEnvironmentVariables

```typescript
// utils/managedEnv.ts
// 관리자가 설정한 환경변수를 현재 환경에 적용
// managed-settings.json의 env 섹션에서 읽음
applyConfigEnvironmentVariables(managedSettings)
```

## 설정 변경 감지 (changeDetector.ts)

`utils/settings/changeDetector.ts`가 파일 변경을 실시간으로 감지한다.

```typescript
settingsChangeDetector.watch(callback)
// → fs.watch()로 settings.json 감시
// → 변경 시 캐시 무효화 + 콜백 호출
```

세션 중 외부 편집기로 설정을 변경해도 즉시 반영된다.

---

## 설정 검증 (validation.ts)

모든 설정은 Zod 스키마로 검증된다.

```typescript
// utils/settings/validation.ts
filterInvalidPermissionRules(settings)
// → 잘못된 권한 규칙 필터링 + 경고

formatZodError(error)
// → 사용자 친화적 오류 메시지
```

**잘못된 설정 처리:**
- 개별 항목 오류 → 해당 항목 무시, 나머지 사용
- 전체 파일 오류 → 해당 소스 설정 전체 무시
