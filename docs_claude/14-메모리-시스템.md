# 메모리 시스템

## 개요

Claude Code의 메모리 시스템은 두 계층으로 구성된다.

| 계층 | 위치 | 목적 |
|------|------|------|
| **CLAUDE.md** | 프로젝트 파일 | 코딩 규칙, 아키텍처, 지침 |
| **Auto Memory** | `~/.claude/projects/.../memory/` | 대화에서 추출한 개인화 정보 |

---

## CLAUDE.md 로딩 순서

`utils/claudemd.ts`가 우선순위 순서로 파일을 로드한다.

```
낮은 우선순위 (먼저 로드, 나중에 덮어씀)
    1. Managed memory (/etc/claude-code/CLAUDE.md 등) — 기업 전체 지침
    2. User memory (~/.claude/CLAUDE.md) — 개인 전역 지침
    3. Project memory — 현재 디렉토리에서 git root까지 탐색
        - CLAUDE.md
        - .claude/CLAUDE.md
        - .claude/rules/*.md (모든 .md 파일)
    4. Local memory (CLAUDE.local.md) — 개인 프로젝트별 지침 (gitignore)
높은 우선순위 (나중에 로드, 모델이 더 주목)
```

**디렉토리 탐색:** 현재 디렉토리에서 git root 방향으로 올라가며 각 단계에서 파일을 탐색한다.  
현재 디렉토리에 가까운 파일일수록 우선순위가 높다.

### @include 지시문

CLAUDE.md 파일 내에서 다른 파일을 포함할 수 있다.

```markdown
@path/to/other.md           # 상대 경로 (=@./path/to/other.md)
@./relative/path.md         # 명시적 상대 경로
@~/home/path.md             # 홈 디렉토리 기준
@/absolute/path.md          # 절대 경로
```

- 코드 블록 내부에서는 동작하지 않음
- 순환 참조 방지 (처리된 파일 경로 추적)
- 존재하지 않는 파일은 조용히 무시

## Auto Memory 시스템 (memdir/)

`memdir/` 디렉토리가 자동 메모리 파일 시스템을 관리한다.

### 저장 위치

```
~/.claude/projects/<인코딩된-프로젝트경로>/memory/
    MEMORY.md           ← 인덱스 파일 (최대 200줄, 25KB)
    user_role.md        ← 메모리 파일 (프론트매터 + 내용)
    feedback_testing.md
    project_release.md
    ...
```

### MEMORY.md 인덱스

`memdir/memdir.ts`의 `ENTRYPOINT_NAME = 'MEMORY.md'`가 인덱스다.

```markdown
# Memory Index
- [User Role](user_role.md) — 한 줄 설명 (~150자)
- [Feedback: Testing](feedback_testing.md) — ...
```

**제한:**
- 최대 200줄 (`MAX_ENTRYPOINT_LINES`)
- 최대 25KB (`MAX_ENTRYPOINT_BYTES`)
- 초과 시 `truncateEntrypointContent()`로 잘림

### 메모리 타입

```typescript
// memdir/memoryTypes.ts
type MemoryType = 'user' | 'feedback' | 'project' | 'reference'
```

| 타입 | 저장 내용 |
|------|-----------|
| `user` | 사용자의 역할, 선호, 전문성 |
| `feedback` | 작업 방식 지침 (수정 및 확인 모두) |
| `project` | 진행 중인 작업, 목표, 결정 사항 |
| `reference` | 외부 시스템 포인터 (Linear, Slack 등) |

### 메모리 파일 형식

```markdown
---
name: 메모리 이름
description: 한 줄 설명 (인덱스 결정에 사용)
type: feedback
---

메모리 내용...

**Why:** 이유
**How to apply:** 적용 시기
```

## Auto Memory 추출 (extractMemories)

`services/extractMemories/`가 대화에서 자동으로 메모리를 추출한다.

```
대화 종료 / 세션 완료
    │
    └─ extractMemories(messages)
            │
            ├─ Claude API에 메모리 추출 요청
            │   → "이 대화에서 기억할 가치가 있는 것은?"
            │
            ├─ 새 메모리 → memory/ 디렉토리에 파일 생성
            ├─ 기존 메모리 업데이트 → 파일 수정
            └─ MEMORY.md 인덱스 업데이트
```

**비활성화 조건:**
- `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` 환경변수
- `ABLATION_BASELINE` feature flag

## 메모리 관련 경로 (memdir/paths.ts)

```typescript
// 자동 메모리 경로 계산
getAutoMemPath(projectDir)
// → ~/.claude/projects/<hash>/memory/

// 자동 메모리 활성화 여부
isAutoMemoryEnabled()
// → MEMORY.md 파일 존재 여부로 판단

// 경로 오버라이드
hasAutoMemPathOverride()
// → CLAUDE_CODE_AUTO_MEM_PATH 환경변수로 경로 오버라이드 가능
```

## 메모리 로딩 (memdir.ts)

`loadMemoryPrompt()`가 쿼리 전에 메모리를 시스템 프롬프트에 주입한다.

```typescript
// QueryEngine.submitMessage() 내에서 호출
const memoryPrompt = await loadMemoryPrompt(projectDir)
// → MEMORY.md + 개별 메모리 파일 내용을 조합해 반환
// → 시스템 프롬프트의 일부로 Claude에게 전달
```

**관련 메모리 탐색:**

```typescript
// memdir/findRelevantMemories.ts
// 현재 작업과 관련된 메모리만 선택적으로 포함
findRelevantMemories(query, allMemories)
```

## 세션 메모리 (SessionMemory)

`services/SessionMemory/`는 현재 세션 내에서만 유효한 메모리를 관리한다.

세션이 종료되면 Auto Memory로 통합되거나 폐기된다.

---

## 팀 메모리 (TEAMMEM feature)

`memdir/teamMemPaths.ts`는 팀 전체가 공유하는 메모리를 관리한다.

```
private/         ← 개인 메모리 (기본)
team/            ← 팀 공유 메모리 (TEAMMEM feature 활성 시)
    MEMORY.md
    *.md
```

메모리 타입별 기본 범위:
- `user` → 항상 private
- `feedback` → 기본 private, 프로젝트 전체 규칙이면 team
- `project` → team 가능
- `reference` → team 가능
