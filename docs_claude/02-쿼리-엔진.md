# 쿼리 엔진

## 개요

`QueryEngine`은 대화 한 세션의 전체 수명 주기를 담당하는 핵심 클래스다.  
`query.ts`의 `query()` 함수를 내부적으로 호출하며, API 왕복 → 도구 실행 루프를 관리한다.

```
QueryEngine (QueryEngine.ts)
    └── query() (query.ts)         ← API 스트리밍 호출
            └── runTools()         ← 병렬/직렬 도구 실행
                    └── runToolUse() (toolExecution.ts)
```

---

## QueryEngine 클래스 구조

```typescript
class QueryEngine {
  private config: QueryEngineConfig
  private mutableMessages: Message[]          // 대화 히스토리 (가변)
  private abortController: AbortController
  private permissionDenials: SDKPermissionDenial[]
  private totalUsage: NonNullableUsage
  private readFileState: FileStateCache        // 파일 상태 LRU 캐시
  private discoveredSkillNames: Set<string>   // 턴 범위 스킬 탐색 추적
  private loadedNestedMemoryPaths: Set<string>

  async *submitMessage(prompt, options?): AsyncGenerator<SDKMessage>
}
```

**한 세션 = 하나의 QueryEngine 인스턴스.**  
`submitMessage()`를 여러 번 호출해 같은 대화 내에서 여러 턴을 처리할 수 있다.

## submitMessage() — 턴 처리 흐름

```
submitMessage(prompt)
    │
    ├─ 1. 이전 orphaned permission 처리
    ├─ 2. processUserInput() — 슬래시 커맨드 탐지/처리
    ├─ 3. fetchSystemPromptParts() — 시스템 프롬프트 조립
    │       ├── getSystemPrompt() (constants/prompts.ts) — 기본 프롬프트
    │       ├── getUserContext() (context.ts) — git 상태 등 사용자 컨텍스트
    │       └── getSystemContext() (context.ts) — 환경 정보
    │
    ├─ 4. loadMemoryPrompt() — CLAUDE.md 메모리 로드
    ├─ 5. query() — API 스트리밍 호출 루프
    ├─ 6. recordTranscript() — 세션 디스크 저장
    └─ 7. SDKMessage yield — 결과 스트리밍 출력
```

## query() — API 스트리밍 루프 (query.ts)

`query()`는 단일 API 왕복을 담당하는 비동기 제너레이터다.  
도구 결과가 발생하면 재귀적으로 자신을 호출해 다음 턴을 처리한다.

### 핵심 흐름

```
query(messages, systemPrompt, tools, ...)
    │
    ├─ 자동 컴팩트 판단 (calculateTokenWarningState)
    │       └─ 컨텍스트 초과 시 buildPostCompactMessages() → 압축된 메시지로 교체
    │
    ├─ Claude API 스트리밍 호출 (@anthropic-ai/sdk)
    │       ├─ text_delta → AssistantMessage 점진적 업데이트 yield
    │       └─ tool_use_block → ToolUseBlock 수집
    │
    ├─ stop_reason = 'tool_use' 시:
    │       └─ runTools(toolUseBlocks, ...) → 도구 실행
    │               ├─ 동시 실행 가능한 도구 → 병렬 (read-only)
    │               └─ 상태 변경 도구 → 직렬
    │
    ├─ 도구 결과 → UserMessage로 변환 후 messages에 추가
    ├─ 재귀 호출 query(updatedMessages, ...) — 다음 API 왕복
    └─ stop_reason = 'end_turn' 시 종료
```

### 자동 컴팩트 조건

```typescript
// services/compact/autoCompact.ts
calculateTokenWarningState(contextTokens, maxContextTokens)
// → 'warning' | 'critical' | 'overflow' | 'ok'
// 'overflow' 또는 'critical' 시 compactMessages() 호출
```

### Feature-gated 최적화

| 플래그 | 기능 |
|--------|------|
| `REACTIVE_COMPACT` | 반응형 컴팩트 (UI 블로킹 최소화) |
| `CONTEXT_COLLAPSE` | 컨텍스트 접기 (오래된 메시지 축약) |
| `HISTORY_SNIP` | 히스토리 스닙 (SDK 전용 메모리 절약) |
| `EXPERIMENTAL_SKILL_SEARCH` | 스킬 프리패치 |

## 시스템 프롬프트 조립 (fetchSystemPromptParts)

`utils/queryContext.ts`의 `fetchSystemPromptParts()`가 세 부분을 조립한다.

```typescript
{
  defaultSystemPrompt: string[]   // constants/prompts.ts에서 생성
  userContext: { [k]: string }    // git 상태, cwd, 프로젝트 정보 등
  systemContext: { [k]: string }  // OS, 날짜, 환경변수 등
}
```

`customSystemPrompt`가 설정되면 `defaultSystemPrompt`와 `systemContext`를 건너뛴다.

`services/tools/toolOrchestration.ts`가 도구 블록 배열을 처리한다.

```typescript
// 도구를 두 그룹으로 분리:

// 2. isConcurrencySafe = false → 직렬 실행 (파일 쓰기, 쉘 실행 등)

// 최대 동시 실행 수: CLAUDE_CODE_MAX_TOOL_USE_CONCURRENCY (기본 10)
```
