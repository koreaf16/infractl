# 상태 관리

## 개요

Claude Code의 상태 관리는 **두 계층**으로 구성된다.

| 계층 | 위치 | 특성 |
|------|------|------|
| `bootstrap/state.ts` | 전역 모듈 변수 | 초기화 후 불변, React 외부 |
| `AppState` | React Context + Store | 변경 가능, UI와 동기화 |

---

## Store — 핵심 저장소

`state/store.ts`는 Redux와 유사한 경량 저장소를 구현한다.

```typescript
export type Store<T> = {
  getState: () => T
  setState: (updater: (prev: T) => T) => void
  subscribe: (listener: Listener) => () => void
}

export function createStore<T>(initialState: T, onChange?: OnChange<T>): Store<T>
```

**동작 방식:**
- `setState`는 updater 함수를 받아 이전 상태를 새 상태로 교체
- `Object.is()` 비교로 동일 참조면 리스너 호출 생략 (불필요한 리렌더링 방지)
- `subscribe`는 언서브스크라이브 함수를 반환

## AppState 타입 구조

`state/AppStateStore.ts`에 정의된 전체 앱 상태. `DeepImmutable<T>` 래퍼로  
직접 돌연변이(mutation)를 타입 수준에서 금지한다.

### 핵심 필드

```typescript
type AppState = DeepImmutable<{
  // 설정
  settings: SettingsJson
  mainLoopModel: ModelSetting
  verbose: boolean

  // UI 상태
  statusLineText: string | undefined
  expandedView: 'none' | 'tasks' | 'teammates'
  footerSelection: FooterItem | null

  // 권한
  toolPermissionContext: ToolPermissionContext

  // 에이전트/팀
  agent: string | undefined
  kairosEnabled: boolean
  selectedIPAgentIndex: number

  // Bridge/원격
  remoteSessionUrl: string | undefined
  remoteConnectionStatus: 'connecting' | 'connected' | 'reconnecting' | 'disconnected'
  replBridgeEnabled: boolean
  replBridgeConnected: boolean
  replBridgeSessionActive: boolean
  // ... 기타 bridge 상태들
}> & {
  // DeepImmutable 제외 필드 (함수 타입 포함)
  tasks: { [taskId: string]: TaskState }
  agentNameRegistry: Map<string, AgentId>
  foregroundedTaskId?: string

  // MCP 상태
  mcp: {
    clients: MCPServerConnection[]
    tools: Tool[]
    commands: Command[]
    resources: Record<string, ServerResource[]>
    pluginReconnectKey: number
  }

  // 플러그인 상태
  plugins: {
    enabled: LoadedPlugin[]
    disabled: LoadedPlugin[]
    commands: Command[]
    errors: PluginError[]
    installationStatus: { ... }
    needsRefresh: boolean
  }

  agentDefinitions: AgentDefinitionsResult
  fileHistory: FileHistoryState
  attribution: AttributionState
}
```

### CompletionBoundary — 완료 경계 추적

```typescript
type CompletionBoundary =
  | { type: 'complete'; completedAt: number; outputTokens: number }
  | { type: 'bash'; command: string; completedAt: number }
  | { type: 'edit'; toolName: string; filePath: string; completedAt: number }
  | { type: 'denied_tool'; toolName: string; detail: string; completedAt: number }
```

도구 실행 완료 시점을 기록. speculative execution(투기적 실행)과 연동하여  
"어디까지 수행했는가"를 추적한다.

### SpeculationState — 투기적 실행 상태

```typescript
type SpeculationState =
  | { status: 'idle' }
  | {
      status: 'active'
      id: string
      abort: () => void
      startTime: number
      messagesRef: { current: Message[] }    // 뮤터블 ref (성능)
      writtenPathsRef: { current: Set<string> }
      boundary: CompletionBoundary | null
      isPipelined: boolean
      // ...
    }
```

사용자가 응답 중에 다음 입력을 준비할 때, 미리 추론을 시작하는 최적화.  
`isPipelined`가 true이면 파이프라인 방식으로 동작.

## AppState.tsx — React Context Provider

`state/AppState.tsx`는 `createStore`로 생성된 저장소를 React Context로 노출한다.

```typescript
// Context 사용 패턴
const { getState, setState, subscribe } = useContext(AppStateContext)

// 상태 읽기
const settings = getState().settings

// 상태 변경 (항상 순수 함수 updater 사용)
setState(prev => ({ ...prev, verbose: true }))
```

컴포넌트는 Context를 통해 저장소를 구독하고, 변경 시 리렌더링된다.

## state/selectors.ts — 메모이즈 셀렉터

파생 상태를 계산하는 선택자 함수들. `lodash.memoize`로 결과를 캐싱해  
동일 입력에 대한 재계산을 방지한다.

```typescript
// 예: 활성 MCP 도구만 필터링
export const getActiveMcpTools = memoize(
  (state: AppState) => state.mcp.tools.filter(t => t.isEnabled(...))
)
```

---

## state/onChangeAppState.ts — 상태 전환 훅

AppState가 변경될 때 사이드이펙트를 실행하는 핸들러.

주요 트리거:
- 태스크 상태 변경 → 알림 발송
- 설정 변경 → 파일 저장
- MCP 연결 상태 변경 → UI 업데이트

---

## 상태 변경 패턴

### 컴포넌트에서 변경

```typescript
const { setState } = useContext(AppStateContext)

// 올바른 방식: 순수 함수 updater
setState(prev => ({
  ...prev,
  statusLineText: '처리 중...',
}))
```

### 도구/서비스에서 변경 (TaskContext 사용)

```typescript
// Task 실행 컨텍스트를 통해 상태 접근
const { setAppState, getAppState } = taskContext

setAppState(prev => ({
  ...prev,
  tasks: {
    ...prev.tasks,
    [taskId]: { ...prev.tasks[taskId], status: 'completed' },
  },
}))
```

## 불변성 보장

`DeepImmutable<T>` 타입은 TypeScript 수준에서 모든 필드를 `readonly`로 만든다.

```typescript
// 타입 오류 발생 — DeepImmutable이 막음
state.settings.model = 'new-model' // ❌ 컴파일 오류

// 올바른 방식: 새 객체 생성
setState(prev => ({
  ...prev,
  settings: { ...prev.settings, model: 'new-model' },
}))
```

단, `tasks`와 `agentNameRegistry`는 함수 타입을 포함하므로 `DeepImmutable`에서 제외.
